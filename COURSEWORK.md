# Двунаправленная дистилляция знаний между LLM и моделями последовательностей событий

Курсовая работа. ВШЭ, 2026.

---

## Аннотация

В работе исследуется передача знаний между большими языковыми моделями (LLM) и специализированными моделями для событийных последовательностей (CoLES) в задачах классификации банковских клиентов. Рассматриваются оба направления передачи: от LLM к структурной модели (через дистилляцию эмбеддингов и мягких меток) и от структурной модели к LLM (через обогащение промпта соседями). Проводится систематическое сравнение трёх типов учительских сигналов и четырёх стратегий обогащения промпта на трёх публичных датасетах транзакций (Gender, Rosbank, Age). Основной результат: обогащение промпта ближайшими соседями из CoLES-пространства даёт прирост +26 пп ROC-AUC независимо от размера LLM в диапазоне 4B–671B параметров; узкое место качества — ретрив, а не мощность языковой модели. Одностороннее контрастное выравнивание (LATTE) превосходит двунаправленные методы на всех датасетах.

## 1. Введение

### Задача

Транзакции клиента банка — это последовательность событий: дата, сумма, категория покупки (MCC-код). По ней нужно предсказать пол, возрастную группу или вероятность оттока. Публичные датасеты, используемые в работе, содержат от 1M до 27M транзакций и от 5K до 30K клиентов — типичный масштаб для розничного банка.

Для таких задач стандартный подход — рекуррентные модели (GRU, LSTM) с самообучением, например CoLES. Они обучаются без разметки, быстро работают в инференсе и дают хороший ROC-AUC. Слабая сторона: они не используют семантику категорий транзакций — MCC-код 5814 ("Restaurants") и 5912 ("Pharmacies") для модели не имеют связи, хотя для человека это очевидно разные паттерны.

Языковые модели понимают семантику MCC-кодов через предобученные веса, но без дополнительного контекста о клиенте работают около случайного уровня (0.5 AUC на бинарных задачах) и дорого стоят в инференсе по сравнению с GRU.

### Идея

Передавать знания между двумя типами моделей в обоих направлениях:

- LLM учит структурную модель лучше представлять клиентов (через дистилляцию эмбеддингов)
- Структурная модель помогает LLM делать предсказания (через обогащение промпта соседями)

### Исследовательские вопросы

**RQ1.** Даёт ли двунаправленная передача знаний больше, чем односторонняя?

**RQ2.** Какой тип сигнала лучше работает в каждом направлении?

**RQ3.** Как размер LLM влияет на качество в обоих направлениях?

### Научная новизна

Работа вносит следующий вклад по сравнению с существующими публикациями:

1. Впервые в одной постановке систематически сравниваются три типа учительского сигнала от LLM к CoLES (response-based, feature-based, relation-based) согласно таксономии [Gou et al., 2021] на трёх публичных транзакционных датасетах.
2. Впервые систематически сравниваются четыре стратегии обогащения промпта LLM данными из структурного пространства (None, Prediction, Explanation, Retrieval).
3. Установлено, что прирост от kNN-обогащения (+26 пп ROC-AUC) инвариантен к размеру LLM в диапазоне 4B–671B параметров — ранее это свойство не исследовалось.
4. Показано, что двунаправленная дистилляция (mutual KL, RAMD) не превосходит одностороннее выравнивание LATTE ни на одном из датасетов (отрицательный результат).
5. Установлено, что kNN-обогащение не работает на 4-классовой задаче (Age) при любом LLM, что указывает на роль качества CoLES-ретрива как узкого места.

## 2. Связанные работы

### Модели для событийных последовательностей

CoLES [Babaev et al., 2022] — метод самообучения на транзакционных последовательностях через контрастную функцию потерь InfoNCE [van den Oord et al., 2018]. Модель не требует меток: она учится сближать представления разных окон одного клиента и разводить представления разных клиентов. После обучения эмбеддинги используются как признаки для downstream-классификатора. CoLES стал стандартным baseline для задач на банковских транзакциях, потому что не требует разметки и масштабируется на миллионы клиентов.

LATTE [Babaev et al., 2025] расширяет CoLES: во время файнтюнинга добавляется контрастный лосс между эмбеддингами CoLES и текстовыми эмбеддингами LLM — по аналогии с CLIP [Radford et al., 2021], который выровнял изображения и тексты через contrastive alignment. Так структурная модель перенимает геометрию языкового пространства, не теряя классификационного сигнала. Эта работа является прямой основой для нашего метода в направлении LLM к CoLES.

LLM4ES [Babaev et al., 2024] показал, что замороженные LLM дают полезные текстовые эмбеддинги транзакционных профилей клиентов. Лучший результат даёт усреднение скрытых состояний по последним 8 слоям модели и затем masked mean-pooling по токенам. Этот протокол извлечения эмбеддингов используется во всех наших LATTE-экспериментах.

### Дистилляция знаний

Классическая дистилляция знаний [Hinton et al., 2015] переносит знания через мягкие метки: ученик обучается минимизировать KL-дивергенцию между своим распределением и распределением учителя. Стандартный forward KL усредняет моды: ученик пытается охватить все варианты, которые учитель считает вероятными, и в итоге размазывается. MiniLLM [Gu et al., ICLR 2024] предложил reverse KL: ученик фокусируется на тех регионах пространства, где учитель наиболее уверен, и не тратит ёмкость на маловероятные исходы. В данной работе мы используем reverse KL в методах Response-based и RAMD. Таксономию типов учительских сигналов (response-based, feature-based, relation-based) мы берём из обзорной работы по дистилляции знаний [Gou et al., 2021].

### In-context learning и обогащение промптов

GPT-3 [Brown et al., 2020] показал, что LLM способны решать задачи по нескольким демонстрационным примерам в промпте без дополнительного обучения (few-shot in-context learning). Качество при этом сильно зависит от выбора примеров. Retrieval-Augmented Generation [Lewis et al., 2020] формализовал это как задачу ретрива: релевантные документы добавляются в контекст модели автоматически, что устраняет зависимость от ручного выбора. Цепочка рассуждений (CoT) [Wei et al., 2022] дополнительно улучшает качество за счёт пошаговых объяснений перед финальным ответом. В данной работе все LLM-эксперименты с обогащением промпта используют CoT при temperature=0.

Применительно к структурированным данным TabR [Gorishniy et al., ICLR 2024] показал, что добавление ближайших соседей из обучающей выборки улучшает предсказания табличных моделей. FT-Transformer [Gorishniy et al., NeurIPS 2021] продемонстрировал, что трансформеры конкурентоспособны на табличных данных с GBDT. Наш метод kNN-обогащения объединяет идеи RAG и TabR: соседи ищутся в структурном пространстве CoLES, а не по текстовой близости, и подаются LLM как few-shot контекст с CoT.

### Итоговый gap

Существующие работы рассматривают один из двух сценариев: либо дистилляцию от LLM к структурной модели, либо обогащение промпта LLM внешними данными. Ни одна работа не сравнивала систематически все три типа учительских сигналов на транзакционных данных и все четыре стратегии обогащения промпта в одной постановке.

Открытым остаётся и вопрос о зависимости качества от размера LLM: в каком направлении больший LLM даёт больший прирост? Для LATTE это вопрос о том, даёт ли более богатое LLM-пространство лучшие ориентиры для CoLES. Для kNN-обогащения это вопрос о том, способна ли более мощная модель лучше использовать структурный контекст от CoLES. Практическая важность ответа очевидна: если размер не влияет, можно использовать дешёвые локальные модели вместо дорогого API.

## 4. Методы

### 4.1. CoLES (базовая линия)

CoLES — самообучаемая контрастная модель для последовательностей событий.

MCC-коды и типы транзакций кодируются через таблицы эмбеддингов, суммы берутся напрямую. Всё подаётся в GRU или LSTM, на выходе вектор клиента размером 1024 (Gender, Rosbank) или 800 (Age).

Метки классов при обучении не используются. От каждого клиента нарезается 5 случайных окон транзакций. Окна одного клиента считаются похожими (positive pair), окна разных нет (negative pair). Модель обучается через InfoNCE loss.

После обучения извлекаем эмбеддинги всех клиентов и обучаем LightGBM поверх них.

Это нижняя граница качества, от которой меряется прирост всех методов.

### 4.2. LATTE

Метод в два этапа.

**Этап 1: получаем LLM-эмбеддинги (учитель).**

1. Берём транзакции каждого клиента и переводим в текст: количество транзакций, средний чек, топ-категории по MCC.
2. Прогоняем этот текст через Qwen2.5-3B. Веса модели не трогаем.
3. Из последних 8 слоёв усредняем скрытые состояния сначала по слоям, потом по токенам. Получаем один вектор 2048 чисел на клиента.

**Этап 2: файнтюним CoLES с двумя лоссами.**

1. Загружаем обученный CoLES из раздела 4.1.
2. На каждом батче прогоняем клиентов через CoLES, получаем CoLES-эмбеддинги.
3. Через MLP-проекцию переводим и CoLES-эмбеддинг, и LLM-эмбеддинг в общее пространство 128 измерений.
4. Считаем два лосса одновременно:

```
L = (1 - a) * L_классификация + a * L_контрастный
```

L_классификация BCE для бинарных задач, CE для возраста. CoLES учится правильно классифицировать.

L_контрастный — симметричный InfoNCE (по аналогии с CLIP). Для батча из N клиентов строится матрица попарных косинусных сходств между CoLES-проекциями и LLM-проекциями. Целевые пары стоят на диагонали. Лосс считается как среднее двух cross-entropy: от строк к столбцам и от столбцов к строкам:

```
L_InfoNCE = 0.5 * [CE(sim(z_c, z_t) / τ, diag) + CE(sim(z_t, z_c) / τ, diag)]
```

где z_c — CoLES-проекция, z_t — LLM-проекция, τ=0.07 — температура, diag — индекс правильной пары. Нормализация по L2 перед умножением.

В итоге CoLES подтягивает свои векторы под пространство LLM и при этом не теряет классификационный сигнал.

Коэффициент a=0.1 выбран через ablation, см. раздел 6.1.

### 4.3. LATTE + mutual KL

Расширение LATTE: вместо замороженного LLM обе модели обновляют веса одновременно.

LLM: Qwen2.5-3B с LoRA-адаптером (r=16, lora_alpha=32, target modules: q, k, v, o). На CoLES и LLM добавляются отдельные классификационные головы.

Лосс из трёх компонент:

```
L = α_cls * (BCE_coles + BCE_llm) / 2
  + α_cont * L_InfoNCE
  + α_mut * (BCE(P_coles, P_llm.detach()) + BCE(P_llm, P_coles.detach())) / 2
```

Третий член — symmetric cross-entropy между sigmoid-вероятностями двух моделей: каждая модель обучается воспроизводить soft predictions другой. Размер батча 16 (ограничение памяти из-за совместного хранения CoLES и LLM).

Для LLM-эмбеддингов в этом методе используется усреднение по последним 4 слоям (в отличие от 8 в standalone LATTE). Всего проверено три конфигурации α: (0.7, 0.2, 0.1), (0.5, 0.3, 0.2), (0.8, 0.1, 0.1).

### 4.4. RAMD

Метод в два шага. Смысл: сначала CoLES помогает LLM (через ретрив соседей), потом LLM помогает CoLES (через дистилляцию).

**Шаг 1: получаем soft labels от LLM для всего train.**

1. Берём train-выборку и делим на 5 фолдов (стратифицированно).
2. Для каждого клиента из out-of-fold берём его CoLES-эмбеддинг.
3. Через cosine kNN ищем 10 ближайших соседей в оставшихся фолдах.
4. Строим промпт: профиль клиента + "Похожие клиенты: 7 male, 3 female. Кто этот клиент?"
5. Отправляем в LLM, получаем вероятность класса (soft label).
6. Повторяем для всех фолдов. Итого у каждого train-клиента есть soft label без утечки.

**Шаг 2: файнтюним CoLES против этих soft labels.**

1. Загружаем CoLES из раздела 4.1.
2. Обучаем с двумя лоссами:

```
L = (1 - a) * CE(y_true) + a * KL(P_student || P_teacher_OOF)
```

CE удерживает от ухода от правильных меток. Второй член — reverse KL (по MiniLLM, 2024):

```
KL_rev = KL(P_student || P_teacher) = sum_y P_s(y) * log(P_s(y) / P_t(y))
```

В отличие от forward KL (который минимизирует KL(P_t || P_s) и заставляет ученика охватить все моды учителя), reverse KL позволяет ученику фокусироваться на тех классах, в которых LLM наиболее уверена. Это полезно, когда soft labels учителя шумные: ученик не пытается воспроизвести неуверенные предсказания.

### 4.5. Методологические решения

**Почему InfoNCE, а не MSE для выравнивания.** MSE-потеря между эмбеддингами фиксирует абсолютные значения, что чувствительно к масштабу и сдвигу. InfoNCE оптимизирует относительное сходство: правильная пара должна быть ближе всех в батче. Это устойчивее к различию в нормировках двух пространств и согласовано с идеей CLIP.

**Почему MaxAbsScaler перед LightGBM.** LightGBM нечувствителен к масштабу признаков, но MaxAbsScaler уменьшает числовые аномалии в эмбеддингах после разных трансформаций. Fit только на train — чтобы не допустить утечки из test.

**Почему OOF для RAMD soft labels.** Если обучать LLM на тех же клиентах, что и CoLES, и потом брать LLM-предсказания как soft labels для CoLES, возникает утечка: LLM видела эти клиенты при обучении. 5-fold OOF гарантирует, что soft label для каждого клиента получена от LLM, которая его не видела в обучении.

### 4.6. Три типа учительских сигналов (RQ2, от LLM к CoLES)

Таксономия по [Gou et al., 2021]:

| Тип | Что CoLES получает от LLM | Как реализовано |
|-----|--------------------------|-----------------|
| Response-based | Вероятности классов (soft labels) | LightGBM на LLM-эмбеддингах выдаёт OOF-вероятности, CoLES учится через reverse KL |
| Feature-based | Сам LLM-эмбеддинг (2048-мерный) | LLM-эмбеддинг конкатенируется с CoLES-эмбеддингом, LightGBM на объединённом векторе (3072 для Gender/Rosbank, 2848 для Age) |
| Relation-based | Геометрия LLM-пространства | InfoNCE между проекциями CoLES и LLM; это то же самое что LATTE (раздел 4.2) |

### 4.7. Четыре типа обогащения промпта (RQ2, от CoLES к LLM)

LLM: Qwen2.5-7B-Instruct, 4-bit NF4, режим CoT, temperature=0. Для каждого клиента строим промпт из профиля транзакций плюс одно из дополнений:

| Тип | Источник | Что добавляется в промпт |
|-----|----------|--------------------------|
| None | нет | только профиль клиента |
| Prediction | XGBoost | "XGBoost предсказывает male с вероятностью 0.73" |
| Explanation | XGBoost SHAP | топ-5 фичей с весами: "высокие траты на транспорт (+0.4)..." |
| Retrieval (kNN) | CoLES kNN | "Похожие клиенты: 7 male, 3 female", 10 соседей из train по cosine |

## 5. Эксперименты

### 5.1. Настройки

Seed фиксируется везде: random, numpy, torch, cuda, pytorch-lightning, PYTHONHASHSEED, cudnn.deterministic=True. В API-запросах seed=42.

В методах с валидацией тест смотрится только на эпохе с лучшим val — так исключается overfitting по тестовой метрике.

Железо: RTX 3090 24GB для локальных LLM (4-bit NF4), OpenRouter API для моделей крупнее 7B.

Метрики: ROC-AUC для Gender и Rosbank, Accuracy для Age.

**Downstream-классификатор LightGBM** (одинаков для всех методов):

| Параметр | Бинарные задачи | Age (4 класса) |
|----------|----------------|----------------|
| n_estimators | 500 | 1000 |
| learning_rate | 0.02 | 0.02 |
| max_depth | 6 | 12 |
| num_leaves | — | 50 |
| subsample | 0.5 | 0.75 |
| colsample_bytree | 0.75 | 0.75 |
| reg_alpha / reg_lambda | 1 / 1 | 1 / 1 |

## 7. Обсуждение

**Почему LATTE работает лучше двунаправленных методов.**
LATTE даёт +0.9 пп AUC на Gender и +0.3 пп на Rosbank при α=0.1. Mutual KL и RAMD не превосходят его ни на одном датасете. Вероятная причина: в LATTE LLM заморожен и является стабильным учителем. При взаимном обновлении весов (mutual KL) два сигнала конкурируют, и contrastive-лосс становится нестабильным. Это согласуется с тем, что при увеличении α в ablation-исследовании (α=0.3 даёт 0.8654 против 0.8713 при α=0.1) слишком сильный contrastive-сигнал уже вредит.

**Асимметрия между двумя направлениями.**
Прирост от kNN-обогащения (+26 пп AUC) несопоставимо больше, чем прирост от дистилляции LLM в CoLES (+0.9 пп). Это показывает, что LLM полезнее как инструмент инференса с контекстом, чем как учитель для CoLES. Контрастная дистилляция улучшает представления CoLES, но LightGBM поверх эмбеддингов и без того хорошо работает — потолок уже высокий. У LLM без контекста потолок низкий (около случайного), а kNN-контекст поднимает его сразу.

**Размер LLM не важен для kNN-задачи.**
Модели от 4B до 671B параметров дают одинаковый прирост. Это говорит о том, что основная работа выполняется CoLES на этапе поиска соседей: модель структурирует пространство так, что ближайшие соседи имеют тот же класс. LLM просто голосует по меткам соседей — и для этого достаточно модели в 4B. Практический вывод: для kNN-обогащения не нужен дорогой API, можно запускать любую доступную модель.

**Почему Age не работает.**
На 4-классовой задаче (Age) kNN-обогащение не даёт прироста ни при каком LLM. Скорее всего, CoLES-пространство плохо разделено по возрасту — транзакционные паттерны возрастных групп менее различимы, чем пол или факт оттока. Если соседи в CoLES-пространстве разных классов перемешаны, LLM не может извлечь нужный сигнал из их меток. Это же объясняет, почему feature-based дистилляция даёт лучший прирост на Age: конкатенация LLM-эмбеддинга с CoLES-эмбеддингом добавляет семантику, которой нет в самом CoLES-пространстве.

## 9. Заключение

В работе систематически исследована двунаправленная передача знаний между LLM и специализированными моделями на событийных последовательностях. Ниже — ответы на три исследовательских вопроса.

**RQ1 (двунаправленность vs одностороннесть).** Двунаправленные методы (LATTE + mutual KL, RAMD) не превосходят одностороннее выравнивание LATTE ни на одном из трёх датасетов. Максимальный прирост — у LATTE (+0.87 пп на Gender). Гипотеза: стабильный замороженный учитель (LATTE) эффективнее нестабильного взаимного обновления.

**RQ2 (лучший тип сигнала).** В направлении LLM → CoLES relation-based сигнал (LATTE) лучше всего на Gender, feature-based (конкатенация эмбеддингов) — на Rosbank и Age. В направлении CoLES → LLM kNN-обогащение даёт прирост +26 пп, что несопоставимо больше, чем предсказание XGBoost (+1 пп) или объяснение SHAP (+11 пп).

**RQ3 (размер LLM).** Для LATTE сравнение по размеру ограничено 7B. Для kNN-обогащения: размер LLM в диапазоне 4B–671B не влияет на прирост. Узкое место — качество CoLES-ретрива.

Практический вывод: для обогащения промпта не нужна большая модель — любая доступная справляется так же. Для дистилляции в CoLES лучше использовать contrastive alignment с замороженным LLM.

### Направления дальнейшей работы

- **RAMD на Age.** Эксперимент не завершён из-за объёма. Интересно, даст ли дистилляция reverse KL прирост там, где kNN-обогащение не работает.
- **Качество CoLES-ретрива.** Основное узкое место kNN-обогащения — это то, насколько хорошо CoLES-соседи разделены по целевому признаку. Исследование LATTE с последующим kNN может улучшить ретрив и в итоге поднять качество LLM-предсказаний.
- **LATTE с большим LLM-учителем.** Из-за ограничений железа LATTE тестировался только с Qwen2.5-3B. Доступ к скрытым слоям 7B+ через API недоступен. Перспективно попробовать более крупные учители через локальный запуск с дополнительным GPU.
- **Мультимодальная постановка.** kNN-обогащение работает как in-context few-shot learning. Следующий шаг — дообучить LLM на синтетических разъяснениях CoLES-ретрива, чтобы модель могла генерализировать, а не только голосовать по меткам соседей.
